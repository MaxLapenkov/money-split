# MVP Test Plan

## Purpose
Единый чеклист проверки MVP перед демо/релизом: функциональность, интеграции Telegram, безопасность и UX.

## Test Environment
- Автотесты расчётов (балансы, сплит, формат денег): `bun test` в корне репозитория.
- Telegram iOS client.
- Telegram Android client.
- Desktop/web fallback (ограниченный сценарий).
- Supabase test project с включенным RLS.

## 1) Auth and Session
- [ ] Открытие Mini App в Telegram создает/обновляет пользователя.
- [ ] Session cookie выставляется после auth.
- [ ] Невалидный `initData` возвращает корректную ошибку.
- [ ] Повторный заход с активной сессией не требует повторного auth.

## 2) Home and Create Group
- [ ] На Home отображаются CTA "Создать группу" и список групп.
- [ ] Создание группы с валидными данными успешно.
- [ ] В форме группы валюта заблокирована на `RUB`.
- [ ] Без дополнительного участника форма не отправляется.
- [ ] Ошибки `react-hook-form + zod` показываются корректно.

## 3) Invite Flow and Binding
- [ ] Кнопка "Пригласить друзей" генерирует invite-ссылку.
- [ ] Telegram share открывается и содержит корректную ссылку.
- [ ] Переход друга по invite открывает нужную группу.
- [ ] При первом входе выполняется выбор участника.
- [ ] Привязка сохраняется, при повторном входе выбор не запрашивается.
- [ ] Невалидный invite обрабатывается user-friendly ошибкой.

## 4) Create Expense Flow
- [ ] Переключение `Расход/Поступление` обновляет динамичную подпись участника.
- [ ] Поля "За что?", сумма, дата и участник обязательны.
- [ ] Успешный submit показывает success toast.
- [ ] После успеха форма очищается для ввода следующей траты.
- [ ] Ошибки submit не теряют введенные данные.

## 5) Group Page (State-based)
- [ ] Без расходов показывается onboarding state.
- [ ] После расходов показываются блоки:
  - `Обзор затрат`
  - `Как закрыть все задолженности?`
  - `Кто уже просмотрел группу?`
- [ ] Кнопка "Посмотреть все расходы" ведет на список операций.
- [ ] Кнопка "Отметить как оплаченное" меняет статус settlement.

## 6) All Expenses Page
- [ ] Отображаются операции с типом, участником, датой и суммой.
- [ ] Корректные знаки сумм (`-` расход, `+` поступление).
- [ ] Empty state отображается при отсутствии операций.

## 7) Settlement and Balances
- [ ] Расчет settlement детерминирован для одинакового input.
- [ ] Балансы корректны после каждой новой операции.
- [ ] Округление в копейках не ломает инвариант сумм.

## 8) View Events
- [ ] Выбор участника (binding) фиксируется как `viewed`.
- [ ] Отметка пользователя фиксируется как `acknowledged` (если кнопка включена).
- [ ] Блок просмотров показывает корректный статус для участников.

## 9) Navigation and Telegram UX
- [ ] `BackButton` скрыта на `/`.
- [ ] `BackButton` видима на внутренних экранах и корректно возвращает назад.
- [ ] `MainButton` опционально синхронизирована с CTA на формах создания (если включена).
- [ ] Haptic feedback работает на ключевых действиях.

## 10) Theming and Layout
- [ ] Light/dark темы синхронизируются с Telegram.
- [ ] Нет визуальных артефактов при смене темы.
- [ ] Safe area учитывается на устройствах с вырезами.
- [ ] Layout корректен при открытии клавиатуры.

## 11) Security and Access
- [ ] Пользователь не видит чужие группы.
- [ ] Невозможно создать binding для чужой группы.
- [ ] RLS включен на всех продуктовых таблицах.
- [ ] Критичные действия выполняются только через server actions.

## 12) Regression Smoke
- [ ] Создание группы -> invite -> join -> binding -> create expense -> group overview работает end-to-end.
- [ ] После refresh состояние группы и данные не пропадают.
- [ ] Базовые действия стабильны в iOS и Android Telegram.
