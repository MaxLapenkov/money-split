# User Flows

## Flow 1: First Launch
1. Пользователь открывает Mini App из Telegram.
2. Клиент отправляет Telegram payload в Next.js API.
3. API валидирует payload, создает/обновляет запись `users` и генерирует токен сессии.
4. Пользователь видит экран с кнопкой "Создать группу".

## Flow 2: Create Group
1. Пользователь вводит название группы.
2. Создается запись в `groups` (`created_by = current user`).
3. Текущий пользователь добавляется в `group_members` с `role = owner`.
4. Остальные участники добавляются с `role = member`.

## Flow 3: Join Group by Invite Link
1. Пользователь A отправляет другу invite-ссылку на группу.
2. Пользователь B открывает Mini App по ссылке и попадает на страницу нужной группы.
3. Система проверяет, есть ли привязка `telegram user -> group participant` для этой группы.
4. Если привязки нет, пользователь B выбирает, какой он участник из списка участников группы.
5. Приложение сохраняет привязку в БД и фиксирует статус `viewed` для блока просмотров группы.
6. При следующих входах в эту группу пользователь B определяется автоматически.

## Flow 4: Add Expense / Income
1. Пользователь выбирает группу.
2. Нажимает "Ввести трату".
3. Выбирает тип: `Расход` или `Поступление`.
4. Выбирает участника (кто заплатил / получил деньги).
5. Выбирает, между кем делить (по умолчанию все участники).
6. Вводит описание, сумму, дату.
7. Создаются записи в `expenses` и `expense_splits`.

## Flow 5: View Balances
1. Приложение считает net balance по участникам группы.
2. Генерирует список рекомендаций "кто кому платит".
3. Показывает итоговый экран с суммами к погашению.
